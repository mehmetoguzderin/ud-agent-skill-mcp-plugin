# Maintenance and handover

`handover_package_build` (096) includes selected data, context/rule identities,
source/license inventory, local reports, open decisions and reproducible next
steps. Verify portable paths and included bytes; a worker-local context pathname
is not a transferable dependency.

`treebank_rename_plan` (097) takes explicit `new_identity_path` and related
repositories. Review mappings, collisions and stale hashes before applying.
`contribution_plan` (084) similarly prepares local work without a remote change.
Avoid broad textual renaming or reconfiguration of unrelated repositories.

`maintenance_report` (095) records policy findings; a cleanup suggestion does not
authorize deletion. Preserve a snapshot (004) before requested changes when useful.
Distinguish product-owned cleanup from user data or shared runtime services.

State what the next maintainer can reproduce, what failed/remains unresolved and
which native/provider or external checks never ran. Retain exact hashes and
findings instead of presenting missing checks as passed. External handoff or
publication requires separate instructions.
