# Public contract

The installed application exposes exactly 102 domain tools, numbered 001–102 in the authoritative [domain catalog](ud-interfaces.json), and two tools in the authoritative [environment catalog](environment.json). Names, parameter names, successful response semantics and existing supported options remain compatible. The JSON catalogs are authored inputs; schema and dispatch generation validates them without reconstructing or overwriting them. [API reference](api-reference.md) links every generated input/result schema and real handler; [provenance](upstream-provenance.json) binds the actual handler source and pinned upstream lock. The [frozen compatibility catalog](../tests/fixtures/compatibility/104-tools-v1.json) independently checks all 104 complete entries.

The coordinator is the local MCP/CLI server; OCI core/render images are workers rather than standalone servers. Workspace access requires explicit roots/grants. Operations snapshot declared inputs, preserve their bytes, verify handoff identities, and validate candidate outputs before authorized host writes. `output_path`/`output_dir_path` remain real authorized export destinations; managed resources supplement them.

Result envelopes contain schema/operation/ID, execution status and elapsed time, actual scope/input hashes/provenance, result, diagnostics, artifacts, check coverage and limitations. Completed linguistic invalidity is not an execution failure. Missing dependencies, incomplete incident collection, cancellation and containment failures cannot become validation success. Detailed per-operation successful results remain authoritative in the generated allOf schemas.

[Wire](schema/worker-wire.schema.json), [state](schema/local-state.schema.json), [context](schema/ud-context.schema.json), [resources](resources.yaml), and [protocol revisions](protocol/) describe their separate boundaries. Schema validation never grants filesystem authority, proves native containment or authorizes repair. Workers receive no engine socket/credentials, ordinary jobs have no networking, and project-authored code requires a fresh OCI sandbox. Userspace supports only trusted built-ins and reports reduced isolation.

Modern and legacy MCP remain supported; stdout carries protocol traffic only. Progress, cancellation, Tasks negotiation and same-tool continuations share request/scope identity. Prompts are optional and intentionally empty; skills use explicit application tools. The [compatibility fixture inventory](../tests/fixtures/compatibility/inventory-v1.json) binds public catalog, protocol, CLI and state cases to their real readers. See [progress](progress.md), [filesystem transactions](filesystem-transactions.md), [plan dependencies](plan-dependencies.md), and [failure codes](failure-codes.md).

The [retained requirements](implementation-requirements.json) and generated [implementation/test inventory](implementation-inventory.json) connect requirements to actual source bytes and original tests. They record no execution success. Complete discovered tests, mutations, native applicability and immutable installed artifacts still require separate source-bound [acceptance](../release/ACCEPTANCE.md).
